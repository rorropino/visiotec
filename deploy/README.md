# VisioTec v2

The corporate website lives in `site/`, separate from existing bounties. The production logo and PHP contact endpoint are retained. Conceptual portfolio graphics are clearly identified; only public links previously tested are shown. GitHub Actions validates HTML structure, Javascript and desktop/mobile browser behavior. On `main`, the deployment requires repository secrets CPANEL_HOST, CPANEL_PORT, CPANEL_USER, CPANEL_PROD_PATH, and CPANEL_SSH_KEY; optional CPANEL_SSH_PASSPHRASE. SSH server continuity pins are reused from SubeTuFlyer; no extra host-key secret is required. Set these through the authorized GitHub secret interface, never in source. The deployment checks the target entry, preserves recognized PHP initialization, dynamic year and hidden form inputs; refuses unmapped PHP blocks, backs up the changed files outside the public root and restores them on failure. Real contact delivery is not tested by the smoke test; the backend is not modified.

## MySQL portfolio and admin
The portfolio is server-rendered from MySQL when configured, with the 19 existing cards retained as a static emergency fallback. Database tables are created and seeded on first connection, never reseeded over user changes. Admin is at /portfolio-admin/. The deployment attempts to provision a dedicated database via the existing cPanel UAPI SSH session when DB secrets are not supplied; if the hosting shell does not permit this, create a dedicated database in cPanel and add DB_HOST, DB_NAME, DB_USER, DB_PASS in GitHub Actions Secrets. PORTFOLIO_SETUP_CODE is optional; if omitted, a random one-time code is created and stored in cPanel at portfolio/private/activation.php, with directory access denied over HTTP and permissions 0600 on runtime files. The initial admin sets a personal password on the setup screen. Existing database configuration is synchronized to current GitHub DB secrets when changed, preserving the setup code. A failed production verification restores the preceding configuration. Never commit config.php or activation.php. Images are stored in MySQL and served only for visible projects. No credentials are printed in CI logs.

### Activation rotation
Existing production configuration uses a SHA-256 digest of a high-entropy one-time activation code instead of the original plaintext. The previous activation.php is removed after successful production checks. The administrator is never reset by deployment; the activation route is unavailable after admin_hash exists. Config backups are private and old activation codes are invalid. Never publish activation code values in Git or CI logs.
